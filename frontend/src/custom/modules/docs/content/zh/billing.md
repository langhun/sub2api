## 步骤 1：区分四个限制

| 项目 | 作用 |
| --- | --- |
| 账户余额 | 所有 Key 共用的可消费余额 |
| 订阅额度 | 指定订阅与时间窗口内可用额度 |
| Key 总额度 | 单个 Key 的累计上限 |
| 5 小时/日/7 日限额 | 单个 Key 的滚动或周期限制 |

## 步骤 2：核对用量

完成最小请求后打开 **用量** 页面并手动刷新。核对时间、请求模型、上游模型、输入/输出 Token、倍率、费用和状态。页面不会保证每 15 秒自动刷新。

## 步骤 3：识别错误

Key 额度耗尽通常返回 `429 API_KEY_QUOTA_EXHAUSTED` 或 OpenAI 风格 `insufficient_quota`；账户余额不足通常为 `403 INSUFFICIENT_BALANCE`。限流 `429` 不一定表示没余额。

## 计费边界

价格取决于模型、分组倍率、Token 与媒体用量。不要假设所有 4xx/5xx 都绝不计费，也不要假设流式中断一定只计算浏览器看到的文本；以本站用量记录和当前政策为准。提交争议时提供时间、模型、金额和 `X-Request-ID`，不要提交 Key。
