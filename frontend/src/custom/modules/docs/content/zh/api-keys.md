## 步骤 1：按客户端分开创建 Key

为 SillyTavern、CLI、服务器程序分别创建 Key，名称写清用途。一个客户端泄露时只需吊销对应 Key。

![API Key 创建与分组设置示意图](asset:common/api-key-create.png "API Key 设置通用示意图")

## 步骤 2：选择分组和模型

分组决定路由到哪些上游账号，也决定可用模型。创建后使用该 Key 请求 `/models`；返回列表比网页中的示例模型名更可靠。

## 步骤 3：设置限制

| 限制 | 建议 |
| --- | --- |
| Key 额度 | 新客户端先用小额度验证 |
| 过期时间 | 临时测试设置明确日期 |
| 5 小时/日/7 日限额 | 防止脚本失控持续消耗 |
| IP 白名单 | 仅适合出口 IP 固定的服务端 |
| IP 黑名单 | 拒绝已知不可信来源 |

列表默认遮罩显示 Key，使用复制按钮取得完整值。修改限制后重新发送最小请求确认配置生效。

## 常见错误

- `API_KEY_DISABLED`：Key 已停用。
- `API_KEY_QUOTA_EXHAUSTED` 或 `insufficient_quota`：Key 自身额度耗尽。
- `ACCESS_DENIED`：IP 规则拒绝了当前客户端。
- 模型不存在：分组未开放模型，或填写了展示名而不是模型 ID。

## 安全边界

Key 额度与账户余额是两层限制：Key 额度充足不代表账户余额充足。IP 判断可能使用受信任代理传来的客户端地址，部署方必须正确配置可信转发来源。轮换 Key 时先创建并验证新 Key，再吊销旧 Key。
