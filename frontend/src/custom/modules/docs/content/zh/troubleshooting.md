## 按固定顺序排查

1. **Key**：重新复制，检查启用、有效期和额度。
2. **分组**：确认 Key 已分配分组。
3. **模型**：确认目标 ID 出现在该 Key 的 `/models`。
4. **Base URL**：查看最终 URL，排除重复 `/v1` 或端点。
5. **协议**：用非流式、无工具的最小请求验证。
6. **上游**：最后再判断容量、限流或临时故障。

## 三个最常见现象

- `401`：Key 或鉴权头错误。
- `403`：未分组、余额、账户或 IP 策略。
- 能列模型但不能聊天：协议能力或高级参数不兼容。

## 提交诊断信息

提供客户端/版本、时间和时区、最终 URL、模型、stream、状态码、脱敏错误体、`X-Request-ID`。截图必须遮住 Key、Cookie、邮箱和对话内容。

## 最小化方法

从 curl 非流式单消息开始，成功后按顺序恢复客户端、流式、system、角色卡、工具和高级参数。每次只改变一项。不要在 401/403 上自动重试；对 429/临时 5xx 尊重 `Retry-After` 或指数退避。
